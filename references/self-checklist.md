# 交付自检清单

## 需求完整性

- [ ] 已写明业务背景、业务目标和当前问题。
- [ ] 已识别使用角色和使用场景。
- [ ] 已区分功能范围、非功能范围和超出范围内容。
- [ ] 已区分已确认内容、合理假设和待确认事项。

## 页面完整性

- [ ] 页面清单覆盖用户提出的页面和主流程。
- [ ] 每个页面都有进入条件、页面结构和离开方式。
- [ ] 列表、新增、编辑、详情、弹窗或抽屉的边界清楚。
- [ ] 每个页面右侧都有完整的需求说明。

## Figma 设计参考

- [ ] 已按当前需求检索默认 Figma 文件的相关页面及历史设计，或记录无法读取的具体限制。
- [ ] 已查看实际采用页面的截图和必要设计属性，不把目录或元数据当作视觉参考。
- [ ] 已复用匹配的组件和流程；与参考的差异有当前需求依据，没有新增无关功能。
- [ ] 配套说明记录了实际参考页面/组件、节点链接和主要调整；未将参考记录加入业务操作界面。

## 字段一致性

- [ ] 原型与说明使用完全一致的字段名称。
- [ ] 字段类型、默认值、必填性和校验规则已说明。
- [ ] 列表字段与表单字段没有遗漏或无依据新增。
- [ ] 多选对象按业务规则在同一条记录内合并展示。

## 按钮交互

- [ ] 每个重要按钮都写明显示条件和可点击条件。
- [ ] 每个重要按钮都有明确的点击处理。
- [ ] 成功、失败和不可操作时都有反馈。
- [ ] 没有只展示文案但无法产生结果的假按钮。

## 状态闭环

- [ ] 所有状态有清晰的文字展示。
- [ ] 已说明状态转换条件和允许的操作。
- [ ] 状态操作完成后列表和说明仍保持一致。
- [ ] 没有出现无法回到业务可用状态的断点。

## 权限说明

- [ ] 每个页面都说明可进入角色。
- [ ] 每个重要操作都说明权限或角色条件。
- [ ] 无权限时的隐藏、只读或错误反馈已说明。

## 异常场景

- [ ] 空结果、加载失败和保存失败已覆盖。
- [ ] 必填校验、格式校验和重复校验已覆盖。
- [ ] 失败时是否保留用户输入已明确。
- [ ] 关闭、取消、返回和重复点击的结果已明确。

## 页面跳转

- [ ] 列表可以进入新增、编辑或详情页面。
- [ ] 新增、编辑页面可以返回列表。
- [ ] 保存成功后的跳转、提示和列表刷新符合需求。
- [ ] 弹窗和抽屉均有可用的关闭路径。

## HTML 可用性

- [ ] 文件包含完整的 html、head 和 body 标签。
- [ ] CSS 和 JavaScript 均内置在单文件中。
- [ ] 没有外部 CDN 或必须联网才能加载的资源。
- [ ] 可直接双击打开并完成核心交互。
- [ ] 没有明显报错、遮挡、错位或横向溢出。

## 原型和需求说明一致性

- [ ] 左右布局比例和分别滚动符合约束。
- [ ] 页面切换时右侧说明同步切换。
- [ ] 原型中的字段、按钮、状态、文案和说明一一对应。
- [ ] 已运行 `python scripts/validate_html.py <html文件>` 并记录结果。

## Web 设计规范引用

- [ ] 当终端为 Web、PC、后台或管理端时，已参考 Axure 页面模板规范文件。
- [ ] 已参考 B 端基础元件库，并检查布局、导航、组件、字号、颜色、间距和反馈表达。
- [ ] Axure 规范仅用于统一视觉和通用组件，没有无依据复制案例业务字段或示例数据。
- [ ] 用户明确需求与 Axure 规范冲突时，已以用户需求为准。
- [ ] 当 `.rplib` 无法解析时，已明确说明限制，没有假装完成规范参考。

## APP整体

- [ ] 是否判断了 APP、H5 或小程序终端类型。
- [ ] 是否使用手机设备外壳。
- [ ] 是否保持左侧 65%、右侧 35% 的布局。
- [ ] 是否未错误使用 Web 后台表格布局。
- [ ] 手机比例是否正常。
- [ ] 手机内容是否被正确裁切。
- [ ] 手机内部是否可以独立滚动。

## APP导航

- [ ] 是否有明确页面标题。
- [ ] 返回按钮是否正常。
- [ ] 页面跳转是否形成闭环。
- [ ] 顶部导航是否固定。
- [ ] 状态栏是否不参与业务滚动。

## APP内容

- [ ] 卡片层级是否清晰。
- [ ] 触摸区域是否足够。
- [ ] 选中态是否明显。
- [ ] 长文字是否正常换行。
- [ ] 是否避免使用宽表格。
- [ ] 列表是否使用移动端卡片。
- [ ] 页面内容是否过度拥挤。

## APP底部操作

- [ ] 底部操作栏是否固定。
- [ ] 是否遮挡最后一条内容。
- [ ] 主按钮是否有禁用状态。
- [ ] 主按钮启用条件是否正确。
- [ ] 是否防止重复提交。
- [ ] 提交失败是否保留用户数据。

## APP状态

- [ ] 是否提供初始状态。
- [ ] 是否提供加载状态。
- [ ] 是否提供空状态。
- [ ] 是否提供异常状态。
- [ ] 是否提供成功状态。
- [ ] Toast 是否限制在手机屏幕内。
- [ ] 成功页是否说明下一步操作。

## APP系统能力

- [ ] 定位失败是否有处理方案。
- [ ] 权限拒绝是否有处理方案。
- [ ] 相机、扫码或相册是否明确为模拟能力。
- [ ] 外部地图跳转是否有说明。
- [ ] 弱网和接口失败是否有反馈。

## APP说明一致性

- [ ] 右侧说明是否与当前 APP 页面同步。
- [ ] 页面字段是否与说明一致。
- [ ] 按钮状态是否与说明一致。
- [ ] 页面跳转是否与说明一致。
- [ ] 成功和异常结果是否与说明一致。
